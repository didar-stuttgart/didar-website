## Authentication Flow (30-second overview)

```
1. User enters password at /admin/login
   ↓
2. POST /api/auth/login verifies against ADMIN_PASSWORD_HASH
   ↓
3. Server creates session in lib/session-store.js (in-memory Map)
   ↓
4. Session token returned as HttpOnly cookie (24h expiry)
   ↓
5. All /api/admin/* routes check session via requireAdminSession()
   ↓
6. Logout deletes session token and clears cookie
```

## Key Files at a Glance

### Session Management (SINGLE SOURCE OF TRUTH)
- **`lib/session-store.js`** ← All sessions stored here
  - `createSession(token)` — creates 24h session
  - `validateSession(token)` — checks if valid
  - `deleteSession(token)` — removes on logout

### Password & Security
- **`lib/admin-auth.js`**
  - `hashPassword()` — PBKDF2-SHA256
  - `verifyPassword()` — compares hash
  - `validatePassword()` — checks complexity rules
  - `generateSessionToken()` — crypto.randomBytes(32)

### Middleware
- **`lib/api-middleware.js`**
  - `requireAdminSession()` — checks auth on all admin endpoints
  - Used by: all `/api/admin/*` routes

### Styling
- **`styles/admin.module.css`**
  - CSS Modules (scoped to avoid conflicts)
  - RTL by default (Persian primary)
  - All admin pages import this

## Authentication Endpoints

| Endpoint | Method | Purpose | Cookie |
|----------|--------|---------|--------|
| `/api/auth/login` | POST | Password → session | Sets `session_token` |
| `/api/auth/logout` | POST | Clear session | Clears `session_token` |
| `/api/auth/verify` | POST | Check if logged in | Reads `session_token` |

All admin data endpoints (`/api/admin/*`) require `session_token` cookie.

## Common Issues

| Issue | Fix |
|-------|-----|
| "Unauthorized" after login | Check `ADMIN_PASSWORD_HASH` is set, session-store.js is used |
| Password doesn't work | Run `scripts/setup-admin.js` to re-hash |
| Session expires immediately | Check cookie Max-Age = 86400 (24h in seconds) |
| Can't export CSV | Check `/api/admin/registrations/export` exists & session valid |

## Architecture in One Picture

```
┌─────────────────────────────────────────────────────────────┐
│                     ADMIN PANEL LAYERS                       │
├─────────────────────────────────────────────────────────────┤
│ Frontend:  pages/admin/*.js (login, dashboard, events, etc) │
│            (React components, useEffect hooks)              │

│ Middleware: lib/api-middleware.js (requireAdminSession)     │
│            (checks session_token from cookie)              │

│ Backend:   pages/api/auth/* (login/logout/verify)          │
│            pages/api/admin/* (events/registrations/etc)    │
├─────────────────────────────────────────────────────────────┤
│ Session:   lib/session-store.js (in-memory Map)            │
│            {token: {createdAt, expiresAt}}                 │
├─────────────────────────────────────────────────────────────┤
│ Database:  Supabase (via createAdminClient with secret key)│
│            Row Level Security bypassed by secret key       │
└─────────────────────────────────────────────────────────────┘
```

## Security Quick Facts

✓ **Strong**: 32-byte random tokens, HttpOnly cookies, PBKDF2 hashing, SameSite protection, RLS at DB level

⚠ **Trade-offs**: Single admin account (no RBAC), in-memory sessions (cleared on restart), no rate limiting on login

## For Future Developers

When modifying admin panel:

1. **Adding a new admin page?**
   - Check session in `useEffect` with `POST /api/auth/verify`
   - Pass `credentials: 'include'` in all fetch calls
   - Redirect to `/admin/login` on 401 response

2. **Adding a new admin endpoint?**
   - Call `requireAdminSession(req, res)` first
   - Use `createAdminClient()` to query Supabase (not public client)
   - Return 401 if session invalid

3. **Changing password logic?**
   - Edit `lib/admin-auth.js` (hashing functions only)
   - Session management is in `lib/session-store.js` (don't duplicate!)
   - Update `scripts/setup-admin.js` if requirements change

4. **Styling updates?**
   - Everything goes in `styles/admin.module.css`
   - Use CSS Modules syntax to avoid conflicts
   - All admin pages already import this file

## One More Thing

**Remember**: The password is set via environment variable during setup, not changed in the UI. If the admin needs to change password, they must:
1. Run `scripts/setup-admin.js` locally
2. Get the new hash
3. Update `.env.local` with new `ADMIN_PASSWORD_HASH`
4. Redeploy

This is intentional (keeps the setup minimal for a single-admin site).
