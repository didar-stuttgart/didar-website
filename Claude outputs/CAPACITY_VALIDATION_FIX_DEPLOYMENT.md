## Changes Applied

### 1. POST Handler (`pages/api/admin/events/index.js`)
- Added strict validation before insert
- Validates with `Number.isInteger()` (not `parseInt`)
- Rejects: 0, negative numbers, decimals, non-numeric values
- Accepts: empty/null (unlimited capacity), positive integers >= 1
- Returns 400 error with message if invalid

### 2. PATCH Handler (`pages/api/admin/events/[slug].js`)
- Same validation logic as POST handler
- Validates before update operation
- Ensures consistent validation across create and edit flows

### 3. Client Form (`pages/admin/events/[slug].js`)
- Updated capacity input from `min="0"` to `min="1" step="1"`
- Provides browser-level validation feedback
- Server-side validation remains authoritative

## Validation Logic

```javascript
if (event.capacity !== null && event.capacity !== undefined && event.capacity !== '') {
  const cap = Number(event.capacity);
  if (!Number.isInteger(cap) || cap < 1) {
    return res.status(400).json({
      error: 'Capacity must be empty or a positive integer (1 or higher)'
    });
  }
  event.capacity = cap;
} else {
  event.capacity = null;
}
```
