Authentication Flow

LOGIN FLOW

1. User navigates to /admin/login
2. Enters password, submits form
3. Frontend: POST /api/auth/login { password }
4. ✓ Backend verifies against ADMIN_PASSWORD_HASH
5. ✓ Generates token: crypto.randomBytes(32) → 64 hex chars
6. ✓ createSession(token) → stored in lib/session-store.js Map
7. ✓ Set-Cookie: session_token={token}; HttpOnly; SameSite=Lax; Max-Age=86400
8. Frontend receives 200, redirected to /admin
9. Dashboard loads, calls POST /api/auth/verify
10. ✓ Session valid → loads stats via /api/admin/stats
LOGOUT FLOW

1. User clicks "خروج" (Logout)
2. Frontend: POST /api/auth/logout
3. ✓ Backend extracts session_token from cookie
4. ✓ deleteSession(token) → removes from Map
5. ✓ Set-Cookie: session_token=; Max-Age=0
6. Frontend redirected to /admin/login
SESSION VALIDATION ON EVERY ADMIN REQUEST

1. User makes request to /api/admin/* (e.g., GET /api/admin/stats)
2. ✓ requireAdminSession() extracts session_token from cookie
3. ✓ validateSession(token) checks if in session-store.js
4. ✓ Checks if token is NOT expired (now < expiresAt)
5. ✗ If invalid → returns false, endpoint returns 401 Unauthorized
6. ✓ If valid → endpoint continues, queries Supabase via admin key

Key Components & Their Roles

🔑 Session Store (Single Source of Truth)

File: lib/session-store.js

Data Structure: Map of {token → {createdAt, expiresAt}}

Functions:
  • createSession(token, expiresAt) — creates 24h session
  • validateSession(token) — checks exists & not expired
  • deleteSession(token) — removes on logout
  • getSessionCount() — returns count of active sessions

Note: This is the ONLY place where sessions are tracked. All authentication checks (login, verify, admin endpoints) use this store.

🔐 Password Security

File: lib/admin-auth.js

Algorithm: PBKDF2-SHA256
  • 16-byte random salt (hex-encoded)
  • 10,000 iterations
  • 64-byte hash output
  • Format: "salt:hash"

Password Requirements:
  • Min 12 characters
  • At least 1 lowercase letter
  • At least 1 uppercase letter
  • At least 1 digit (0-9)
  • At least 1 special character (!@#$%^&*)

Setup: Run scripts/setup-admin.js to generate password hash

🔧 Middleware

File: lib/api-middleware.js

Function: requireAdminSession(req, res)
Usage: Called at the start of every /api/admin/* endpoint
Returns: true if session valid, false otherwise
If false: Endpoint returns 401 Unauthorized

How it works:
  1. Parses cookies from request header
  2. Extracts session_token
  3. Calls validateSession() from session-store.js
  4. Returns boolean result

💾 Supabase & Database Access

File: lib/supabase.js

Public Client (Limited by RLS):
  • Used for: Public reads, form submissions
  • Uses: NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
  • Can: SELECT published events, INSERT registrations
  • Cannot: Read/modify private data

Admin Client (Full Access):
  • Used in: Every /api/admin/* endpoint
  • Uses: SUPABASE_SECRET_KEY (server-side only)
  • Can: Full database access (bypasses RLS)
  • Never exposed to: Browser or frontend code

Security Features

✓ Strong Tokens

32 random bytes (256-bit entropy), impossible to brute-force

✓ HttpOnly Cookies

JavaScript cannot access session token, protects against XSS

✓ SameSite Protection

Cross-site forms cannot submit to admin endpoints, protects against CSRF

✓ Password Hashing

PBKDF2-SHA256 with random salt, never plaintext in code

✓ Row Level Security

Database enforces access control at schema level, second line of defense

✓ Secret Key Isolation

Admin key never sent to browser, only used server-side

Troubleshooting Guide

⚠ "Unauthorized" on dashboard after login
Check: ADMIN_PASSWORD_HASH is set in environment, session-store.js is being used, requireAdminSession() is called in admin routes, cookie is sent with credentials: 'include'
⚠ Password doesn't work despite being correct
Fix: Run scripts/setup-admin.js to re-hash password, verify format is "salt:hash", ensure password meets complexity requirements
⚠ Session expires immediately
Check: Session creation sets expiresAt to 24h from now, cookie Max-Age is 86400 (24 hours in seconds), validateSession() checks date comparison correctly
⚠ Can't export registrations as CSV
Check: /api/admin/registrations/export endpoint exists, content-type header is set to 'text/csv', session is valid when export is requested
